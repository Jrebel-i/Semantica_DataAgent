# 融合检索与 MCP 结果约定

排序参数版本 `1` 使用倒数排名融合，k 为 60；精确、全文、向量、图展开的权重分别为 2、1、1、0.5。无产出表的任务分数乘以 0.5。精确命中或两路及以上命中为高置信度，仅全文命中为中置信度，其他为低置信度；置信度是排序信号，不是概率。

当至少两个不同文档的候选段落都包含查询词时，标记为**可能歧义**并列出段落引用。该保守规则提示调用方核对原文，并不证明口径确有冲突；它只检查已召回的段落和字面查询词。

所有 MCP 工具接受 `cursor`。每页最多 25 条或 12,000 字符；单个值过大时通过 `result_fragment` 返回 JSON 文本片段，客户端应拼接全部片段后解码 JSON。续页必须使用相同工具和参数。每页重新执行工具，因此知识内容变化后应从头分页。

工具输入或业务校验失败返回 `invalid_input`（不可重试）；连接和超时失败返回 `unavailable`（可重试）；其他异常返回 `internal_error`（不可重试）。错误信息与下一步建议使用固定文案，不包含内部异常详情。

## MCP 项目选择

每个 MCP 请求只服务一个项目。优先级固定为：在线 agent 凭据绑定的项目 > 请求显式选择 > 与 REST 相同的缺省规则（能访问默认项目就用默认，否则只有一个可访问项目就用它，否则要求指定）。普通令牌用查询参数 `project` 或请求头 `X-Dataagent-Project` 二选一；两者同时出现且不一致时返回 `invalid_input`。凭据绑定的项目不能被请求参数覆盖，指向其它项目时统一按“项目不存在”拒绝。

未指定项目且令牌可访问多个项目时返回 `invalid_input`，消息以 `请指定项目` 开头并列出可访问的 `id（名称）`。项目不存在、无权限都返回同样的“项目不存在”，不泄露项目是否存在。`get_capabilities` 返回当前解析到的 `project` 与请求者可访问的 `projects`；`ask_dataagent` 在非默认项目上返回明确的工具错误。
