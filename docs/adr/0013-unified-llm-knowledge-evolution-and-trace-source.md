# 统一大模型归纳的知识演进闭环、可插拔对话追踪源与人工审批收口

Status: accepted

第八期 [0010](0010-local-trajectories-and-candidate-generation-gate.md) 与第九期 [0011](0011-query-history-mining-and-data-probed-relationships.md) 分别建设了基于本地工具轨迹与 L2 候选知识代门禁的自主演化，以及纯确定性规则+探活的冷启动发现；同时自然语言纠错抽屉与已确认**知识缺口**在未显式传模型参数时仍会静默退化为模板直拼。整体链路存在本地轨迹与外部 Trace 割裂、L2 候选代过重、冷启动缺少业务可读总结、以及多路提案格式与审批策略不统一等问题。第十一期将三类知识演进来源统一收口，取代 [0010](0010-local-trajectories-and-candidate-generation-gate.md) 与 [0011](0011-query-history-mining-and-data-probed-relationships.md)：

1. **三大知识演进触发源统一经“上下文检索 + LLM 归纳 + L1 静态校验”进入纠错审批**：
   - **交互式纠错与缺口补充**：对话纠错抽屉、已确认**知识缺口**后的「发起纠错」以及对话内 Agent 提交，均默认加载当前知识库检索上下文与配置的默认大模型，允许用户仅用自然语言描述业务规则（不必先手选目标文件或表），由系统自动定位目标并生成规范 Git Diff 或结构化补丁预览；模型不可用时显式提示降级为手工编辑，取消静默口语拼接。
   - **对话回溯演化（自主演化）**：彻底下线本地 `interaction_trajectories` 采集表与重型 L2 候选知识代自动演化循环，改为通过可插拔的**对话追踪源（Trace Source）**插件（Python entry-point，首期内置 `langfuse`）按 `project_id` 与水位线时间窗增量拉取脱敏后的人机对话 `messages`（忽略底层工具调用明细，严禁采集密钥与业务查询结果行），由大模型总结高频口径、隐性纠偏与沉淀内容。支持项目级每日固定时刻/Cron 定时调度与管理员手动按时间窗触发。
   - **历史查询发现（冷启动发现）**：对数仓**查询历史**先做确定性字面量脱敏与模板指纹聚类（压噪控量），再由大模型结合表/字段注释梳理常见查询模式、业务指标口径与常用表使用说明；原有的个人令牌只读**数据探活**（外键重合度核验）保留为管理员按需勾选的可选增强项。
2. **统一落点路由与防重复膨胀约束**：
   - 单表/字段说明、同义词、过滤约束、外键与单指标口径优先落入 `overrides/semantic_overrides.yaml`（防止被每日拉取覆盖）；
   - 跨表业务规则、专题口径与常见问题指南优先检索并合并更新已有 Markdown 文档对应章节；确实无匹配文档时允许建议新建文档（同样以新增文件 Diff 提案进入审批，独立长篇原稿仍保留只追加上传通道）；
   - 提案生成前对已有知识与当前 `pending` 待审批队列执行去重，避免重复刷屏审批列表。
3. **审批策略收口**：
   - 去掉重型 L2 候选知识代自动门禁后，移除 `evolution_require_review=false` 自动直写源目录旁路；三路来源产出的所有**纠错提案**经 L1 静态校验后一律默认进入 `pending` 人工审批队列，审批页统一展示“来源类型 + 原始触发证据（原问题/Trace 摘要/历史 SQL 统计与可选探活证据）+ LLM 归纳理由 + Git Diff”，批准后写回 Git 源目录触发增量构建，并支持一键 `git revert` 回滚。
   - **评测题集（`dev` / `holdout`）**保留为独立的回归评测资产，供管理员按需触发准确率验证，不再阻塞日常演化提案生成。

## Considered Options

- **继续同时维护本地对话/工具轨迹表与外部 Langfuse Trace 双源**：维护两套采集与清理逻辑复杂度高，且工具调用明细噪音大、Token 成本高；团队已部署 Langfuse，收口为可插拔外部 `TraceSource` 只读人机 `messages` 更轻量且易扩展其他 Trace 平台，故放弃本地轨迹表。
- **保留 L2 隔离候选知识代自动合入**：在 1,800+ 表规模下每轮演化临时建候选代并跑全套评测耗时极高，且所有改动仍需业务语义把关；改用 L1 静态校验 + 统一人工审批可在保证零污染的同时显著提速，故放弃自动合入。
- **冷启动发现维持纯确定性机械模板**：虽无幻觉但产出的英文列名/频次模板业务可读性差，难以直接作为知识沉淀；采用“确定性聚类/可选探活取证 + LLM 业务总结润色 + 保留原始统计证据”兼顾准确性与可读性，故采用两段式。

## Consequences

- 旧版 `interaction_trajectories` 表与采集逻辑、旧 L2 候选知识代演化闭环及 `evolution_require_review` 自动放行旁路将在第十一期直接清理下线（不保留旧轨兼容）。
- Langfuse 上报路径须在启用内容采集时附带 `project_id` 与脱敏人机 `messages`，保证外部 `TraceSource` 拉取时按项目严格隔离。
- `CorrectionProposal` 与前端审批视图统一承载三路来源的证据摘要与新建/修改 Markdown Diff 预览。
