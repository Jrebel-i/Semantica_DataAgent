# 知识缺口人工审核

Agent 上报缺口后，项目成员在原有页面查看原问题、缺口说明、登记时间和审核状态。历史记录保留并进入待审核。项目管理员或系统管理员可确认缺口或标记「不接纳」，记录审核人和审核时间。两个决定都是终态，重复或并发提交不得覆盖首个决定。

已确认的记录提供「发起纠错」和「补充知识」。纠错复用现有草稿抽屉，带入原问题和缺口供用户编辑，并走提案审批。补充已有文件走纠错，新资料在同项目使用只追加的源文件预览与上传；服务端在仓库锁内拒绝覆盖、删除和替换。按现有角色及项目状态执行权限检查。确认缺口本身只记录审核决定。

缺口确认只进入人工处理，任何审核状态的缺口都不进入自主提案；轨迹中单独出现上报工具调用时不再计为失败证据，真实失败仍按已有规则处理。保留原有评测集隔离及调度条件。

验证旧库升级、项目与角色隔离、并发决定、项目切换、同项目后续入口及已确认缺口不进入自主演化。
